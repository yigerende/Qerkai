# OpenAI 下游模型名称对齐

入口：系统设置 → 网关转发，位于“强制 OpenAI 上游 WebSocket”上方。默认关闭。

开启后，可以选择全部分组或指定分组，并每行填写一个模型，默认 `gpt-6-astra`。按本次请求的分组和实际发送给上游的模型匹配。

例如：发送 `gpt-6-astra`，上游响应声明 `gpt-5.6-luna`。命中配置时，转发给客户端前把响应的 `model` 改为实际发送给上游的模型 `gpt-6-astra`。HTTP JSON、SSE 事件的 `response.model` 和 WS 返回帧都支持。多个模型分别对齐到各自实际发送给上游的模型；配置了模型映射时，以映射后真正发送的值为准。上游没有返回不同模型时，保留原有映射和协议转换行为。

- 关闭开关、未选中分组、未配置该模型时，沿用原有响应处理。原来的模型映射和协议转换仍按原逻辑执行。
- 不修改发给上游的请求、回答正文、工具参数、用量和计费规则，不改变 WS 连接池选择、复用、重连或 CPA 首帧通知。
- 管理员使用日志在“模型”后增加“下游实际模型”。原有上游响应模型和不一致标记仍保存真实值，降智检测继续使用原有上游证据。
- 历史记录或响应中没有模型声明时显示 `-`，不根据当前配置补造历史值。
- 每次转发/WS 轮次使用独立的配置快照；保存配置后在本实例后续请求生效。其他实例通过原有设置存储读取，最多有 60 秒缓存时间。已开始的流保持本轮规则。

配置字段：`openai_downstream_model_alignment`，包含 `enabled`、`group_ids`、`models`。`group_ids: null` 表示全部分组，`group_ids: []` 表示不选择分组；空模型列表不启用任何模型。
