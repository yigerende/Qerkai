# OpenAI OAuth 拥堵换号

入口：账号管理顶部、刷新按钮前的“拥堵换号”。默认关闭，设置单独持久化。

## 关闭时

继续走原有选号、粘性、排队、重试、HTTP/WS 转发和计费代码。不建立请求迁移状态，不读取 Redis 迁移标记，不运行新增拥堵等待。配置读取有进程内缓存；当前实例保存开关后立即更新缓存，其他实例最多约 5 秒刷新。

已经成功迁移的会话，其新账号就是普通粘性绑定；关闭开关不会把它强行切回旧账号。关闭前已经发送给上游的请求继续原有处理。

## 开启时

- 正常会话仍优先原账号。单纯 80% 占用不会触发迁移。
- 账号满并发时，有健康空闲候选才先等 2 秒，再检查原账号是否仍满。没有候选、只有一个账号、全部账号拥堵，都回到原有有上限排队。
- 最近一分钟至少 5 次样本，其中至少 3 次且占比不低于 30% 的 429/5xx 或网络故障；或至少 3 条且占在途请求 20% 的请求超过 60 秒没有首个网络响应；或占用不低于 80%、至少 5 次样本且至少 30% 首响应超过 15 秒，才视为异常拥堵。
- 迁移目标需要是同请求允许使用的 OpenAI OAuth 账号、占用不高于 50%、没有上述拥堵信号。候选的分组、模型、额度、利润准入、传输能力、优先级和并发槽位仍交给原调度器检查。新会话仅在存在可用健康候选时避开确认异常的账号。
- 同一会话的并发请求共享 Redis 原子迁移标记。目标成功转发后才更新粘性绑定；失败不提交。旧请求不能覆盖或删除新绑定。迁移后 120 秒内不再次做拥堵换号，保护期结束也不会自动回切。
- 只改变请求发出前的选号，不中断在途请求，不增加上游超时，不额外重发，不冷却或暂停原账号。后续原有重试如重新选号，也仍受原有次数和已输出内容限制。
- 本功能用于 HTTP 入站的 Responses、Chat Completions、Messages；上游可为 HTTP、强制 WS 或 BPS。原生 WS 入站、指定 previous_response_id 或 item_reference 的续接、压缩、图片及 Guardian 父会话绑定不参与主动迁移。

## 运行和验证

健康样本只在进程内短期保存，每账号最多 64 条；重启后重新积累。迁移标记有过期时间，普通成功绑定沿用原会话 TTL。Redis 不可用时回退原选号，不绕过原并发限制。没有新增数据库表或迁移。

日志 `openai_congestion_migration_started` 表示已选中迁移目标，`openai_congestion_migrated` 表示成功并提交绑定。它们不是新的使用记录或扣费项。

测试覆盖关闭时与原选择器结果比较、默认关闭和显式保存 false、健康粘性、满载短等、全忙/单账号回退、候选权限、失败不提交、并发迁移、旧请求防覆盖，以及 Redis 原子操作。
