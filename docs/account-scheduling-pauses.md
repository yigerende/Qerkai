# 暂停调度时间与外部查询

## 暂停与恢复

- 启用的降智暂停规则命中，**或者**启用的指定模型 State 有效期要求不满足，都会通过原来的调度开关暂停账号。
- 自动恢复仍需同时满足原恢复规则和启用的 State 有效期要求；手动关闭的账号不会被自动恢复。
- 本次只增加真实开关的暂停时间记录和查询，不增加请求入口拦截，也不新增检测定时器。

## 暂停时间

`scheduling_paused_at` 表示当前这次连续暂停开始的时间，账号列表显示在调度开关下面。

手动、批量、检测、State 检查、重授权等路径统一在数据库写入开关时记录；重复关闭不重置，开启后清除，再次关闭重新计时。账号状态、429 冷却等不等于关闭调度开关。

旧版本已经关闭的账号无法还原真实暂停时间，首次升级从迁移时开始记录，避免根据不准确的历史时间清退。重启和再次执行迁移不会重置已保存时间。

## 查询接口

`GET /api/v1/admin/accounts/scheduling-paused`

使用现有管理员认证（Space 使用推送设置里的管理员登录），不接受普通用户调用。只返回未删除且当前调度开关关闭的账号，不包含令牌或 State 内容，响应禁止缓存。

参数：

- `limit`：每页 1 到 100，默认 100。
- `after_id`：上一页的 `next_after_id`，默认 0。
- `account_ids`：可选，最多 100 个不重复正整数，用逗号分隔。Space 使用已绑定的 Sub2 账号 ID 查询。

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "version": 1,
    "server_now": "2026-09-20T00:10:01Z",
    "accounts": [{
      "account_id": 42,
      "name": "example",
      "platform": "openai",
      "type": "oauth",
      "email": "user@example.com",
      "scheduling_paused_at": "2026-09-20T00:00:00Z",
      "paused_seconds": 601
    }],
    "has_more": false,
    "next_after_id": 0
  }
}
```

`paused_seconds` 由数据库时钟计算并向下取整，调用方不需要比较两台机器的时钟。继续翻页直到 `has_more=false`。

## Space 联动

两个 Space 项目的“推送设置 / Sub2”新增 `scheduling_pause_timeout_seconds`（暂停调度超时移出），默认 0。

开启额度检测且账号允许自动移出时，沿用原额度检测间隔查询；连续暂停秒数**大于**阈值后按该账号原有方式移出空间，再删除 Sub2 账号。手动暂停也计入。手动额度检查沿用同样规则。

0 秒不调用本接口。查询失败、响应不完整、账号或邮箱不匹配均不触发本项清退，原额度规则继续执行。等待空间操作锁后会再次检查暂停状态、暂停起始时间和当前配置，恢复或重新暂停后不使用旧结果清退。删除失败沿用原清理重试，避免重复移出空间。

部署顺序：先更新 Qerkai，再更新两个 Space 项目。新 Space 连接旧版 Qerkai 时，接口失败只跳过暂停超时判断。
