# OpenAI 502/503 业务重试与 WS 内部重连修复方案

日期：2026-09-16

状态：已实现并完成本地验证。后端功能、50/200 并发模拟和桌面/手机页面检查通过，结果见文末。

## 修复目标

针对 `Codex → HTTP/SSE → Qerkai → 强制 WS → OpenAI` 路径，保留 CPA 首字通知立即发送，修复业务重试期间 CPA 通知误挡 WS 内部重连的问题。

业务重试默认只接管此前指定的两种 OpenAI 上游 502/503 错误。现在可在开关下方配置匹配规则，不会默认扩大为所有 502/503 或所有连接故障。

## 1. 补通内部重连

业务重试遇到 WS 故障，先按原有规则内部重连，恢复后继续当次请求。

```text
指定上游 502/503
→ 开始业务重试
→ 遇到 WS 连接故障
→ 执行原有 WS 内部重连
→ 恢复连接后继续当次请求
→ 成功则结束；再次收到指定错误则继续业务重试
```

内部重连的错误分类、次数、退避间隔和时间预算保持原样。连接故障不包装成新的业务重试错误，内部重连不占用业务重试次数。

每次业务重试和内部重连都重新经过原有 WS 连接池调度。优化调度的会话主连接、会话备用连接、公共预热/备用连接及新建连接选择规则未修改。异常退出时原连接仍按已有逻辑标记故障并释放，不保证复用刚报错的连接。

## 2. 统一“还能不能重试”的判断

仅对已经被 502/503 开关接管的请求，补齐内部重连入口及相关连接错误出口的判断：

- 只发过 CPA 通知、空的 `response.created` 等允许的元数据：仍允许恢复。
- 已经输出回答、推理、工具调用或其他实际内容：停止重放。
- 客户端已取消或断开：停止恢复。

复用已有的输出状态判断，不全局取消“已经输出”的保护。CPA 通知继续立即发送，现有响应 ID、事件序号和重复通知处理保持一致。

## 3. 面板新增“WS 内部重试”列

在 502/503 重试菜单面板增加一列，显示本次业务重试期间实际执行的 WS 内部重试累计次数及结果，例如：

- `未发生`
- `2 次，已恢复`
- `5 次，未恢复`

两类计数分开：原有“502/503 业务重试次数”只记录开关触发的业务重试；新列记录内部连接重试。首次连接和仅计划但尚未执行的内部重试不计数。

使用日志仍只记录业务重试次数，与面板原有业务计数保持一致。

## 4. 补全最终停止原因

保留触发业务重试时的上游错误，同时记录最终停止原因和具体错误信息，例如：

- 业务重试次数用尽。
- WS 内部重连次数或时间预算耗尽。
- 业务重试时间预算耗尽。
- 客户端取消或断开。
- 已输出实际内容。
- 无可用账号或其他不可恢复错误。

终态记录不能只展示最初的 503 过载文案，必须能看出最后在哪一步停止。

内部重连确实耗尽时，业务重试不足配置的 5 次也可以结束；但不能仅因为发过 CPA 通知就提前结束。

## 5. 开关关闭与现有行为

- 读取到关闭配置的新请求，不启用上述特殊处理，保持原来的处理路径。
- 在途请求沿用现有配置快照机制，本次不改变开关生效机制。
- 未触发指定业务错误的请求，保持原有 WS 连接恢复行为。
- 不修改 CPA 首字通知的发送时机，不新增请求内容改写。
- 已接管的业务重试在内部恢复时保留完整请求载荷，包括 `include`；未接管或关闭开关时保留旧的内部重试载荷策略。
- 不修改运维“请求错误”的判定规则，最终恢复成功按成功处理。
- 额外耗时包含内部连接恢复时间，成功恢复后不包含后续整段回答的生成时间。

## 6. 验证与验收

- 指定 503 后遇到握手 502/503、读写失败或连接断开，内部恢复后业务成功。
- 故障分别发生在重试通知之前、之后，只有通知时均不误挡内部恢复。
- 内部重连耗尽时正确结束，业务计数和最终停止原因准确。
- 连续指定错误能够执行同账号重试、换账号重试，并遵守累计 5 次业务重试预算。
- 已输出回答、推理或工具内容后不再重放；客户端取消后不继续重试。
- 关闭开关、未触发业务重试时，原有行为保持一致。
- 使用假账号和本地模拟上游执行 50、200 并发混合故障测试，核对响应完整性、两类计数、最终日志和账号隔离。

验收重点：CPA 通知不再误挡内部重连，连接恢复仍走原机制，两类重试计数独立，最终失败原因清楚。

## 7. 可视化匹配规则

开关打开后可配置规则的启用状态、名称、归类状态码（502/503）、关键词和匹配方式（全部/任意），支持新增、删除、排序、恢复默认及粘贴错误事件 JSON 测试匹配。预览和实际转发使用同一个匹配函数；页面预览使用尚未保存的草稿。

默认启用两条规则：

| 归类 | 必须同时包含的内容 |
| --- | --- |
| 502 | `An error occurred while processing your request` 和 `You can retry your request` |
| 503 | `Our servers are currently overloaded` 和 `Please try again later` |

匹配仅针对 WS 的 `error` / `response.failed` 业务错误，忽略大小写并归一化空白。先排除原有 429/限流、上下文超限、安全策略错误及明确的非 502/503 状态码，再匹配错误内容。上游不提供数字状态码时仍可通过内容命中；规则中的状态码是命中后的归类，并非要求上游必须携带同一个数字。多条规则命中时以第一条为准。

未命中或取消勾选的错误回到原有处理路径。删除全部规则表示不接管任何业务错误。未保存过规则的旧配置自动使用默认两条；损坏的规则配置不会扩大匹配范围。在途请求继续使用开始时的配置快照。

## 8. 本地验证记录

使用本地 HTTP/SSE 客户端、真实本地 WebSocket 通信和 5 个模拟账号，不消耗真实 OpenAI 账号额度。以下结果不代表正式环境或真实 OpenAI 上游压测：

- 50、200 并发各 300 条混合故障请求：每轮 300 次业务重试、200 次 WS 内部重连，全部恢复，使用日志每条业务计数为 1。
- 50、200 并发各 500 条连续业务错误请求：每轮 2,000 次业务重试、2,500 次上游请求，全部恢复，同账号及换账号路径通过。
- 握手 502/503、通知前后断连均恢复；持续握手失败记录业务 1 次、WS 5 次和内部次数耗尽原因。
- 已输出正文后停止重放；开关关闭、规则停用、自定义匹配、取消请求、业务预算耗尽、CPA 首帧即时性及响应 ID/序号一致性通过。
- 核对重发载荷的输入、模型、指令、工具、推理和 `include`，恢复成功请求不进入请求错误。
- 设置保存、遗漏字段保留、空规则清除、非法规则拒绝及匹配预览后端测试通过；规则编辑组件测试通过。
- 补充验证只启用 502、只启用 503、全部取消、删除全部规则及关闭总开关：仅启用且命中的规则产生业务重试；其他情况沿用原错误处理，不产生本功能业务计数。保存配置后运行时缓存同步更新。
- 原有 WS 连接池及优化调度回归测试通过；强制 WS、连接池选连接和运维监控页面/错误统计代码没有修改。
- 前端类型检查与生产构建、后端嵌入式构建通过。1440px 桌面与 390px 手机浏览器检查规则编辑、保存请求、匹配预览、重试列和停止原因通过。页面测试使用隔离浏览器内的模拟管理 API；后端真实匹配及配置缓存由上述后端测试验证，未修改实际管理员配置。
- 本地最终构建通过 `http://127.0.0.1:8082` 健康检查；该地址用于本地验收，不代表正式环境已部署。
