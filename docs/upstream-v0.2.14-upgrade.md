# Qerkai 升级上游 0.2.14

日期：2026-10-07。

## 升级范围

- 原 Qerkai：`ef2cd2d6392049c3fbddc689eb04e4e84c061c16`（0.2.9）。
- 合入 Wei-Shaw/sub2api：`3f1a2ea0a760730e3bc528105c00b4ee4f23e469`（0.2.14）。
- 使用三方合并，保留上游提交历史；升级前代码备份分支为 `backup/before-upstream-v0.2.14-ef2cd2d63`。
- 本次不迁入 ranxi/bps-sub2api 的独立 BPS 实现，保留 Qerkai 现有 CPA BPS。

## 保留的二开功能

强制 WS 及分组范围、WS 优化连接池、CPA 首帧、502/503 自动重试、State 采集和注入、代理及多模型配置、降智检测和复检、自动暂停/恢复调度、暂停时间及对外查询接口、CPA BPS、RPM、管理员日志扩展和下游模型显示功能均保留。

原有 268 个二开独有文件全部保留且内容未变。共享文件按新上游接口适配；模型目录同时保留 BPS 模型补充和白名单过滤，并区分普通目录与不支持 System One 的 Codex 目录。Wire 和 Ent 已重新生成。

部署保留 Qerkai 的镜像、服务、容器、数据库、Redis、网络、卷和配置路径。

## 上游行为变化

0.2.14 的新模型目录、合成分组模型路由修复、TypeSafe / System One、Claude 额度 reset、充值优惠阶梯、仪表盘及账号管理改进、安全修复等一并合入。

新建 API Key 默认受到每用户有效 Key 数量和每小时创建数量限制。首次安装不再采用固定的默认管理员邮箱；已有管理员不重新初始化。请求途中 API Key 被删除时，仍完成其余应有结算，避免整笔事务回滚。

### 并发余额预留默认关闭

上游新增 `billing.inflight_reservation`，会改变并发请求的余额准入。Qerkai 将**实际运行默认值和配置示例都设为关闭**，已有配置未填写该项时仍关闭，避免升级后自动启用。

```yaml
billing:
  inflight_reservation:
    enabled: false
```

需要启用时可显式配置为 `true`，或设置 `BILLING_INFLIGHT_RESERVATION_ENABLED=true`。开启后按上游方式估算在途费用，直到异步计费结束才释放；该功能不等于提前完成实际扣费。

### 并发对比

使用相同 Go 版本、`GOMAXPROCS=4`、两套模拟账号和模拟上游，检查完成事件、账号隔离、缓存用量与 WS 连接并发。下表为编译缓存就绪后各 3 次执行的中位耗时，单位 ms，表示整个模拟批次完成时间：

| 路径 | 并发 | 0.2.9 | 0.2.14 |
| --- | ---: | ---: | ---: |
| BPS HTTP | 40 | 15.95 | 15.00 |
| BPS HTTP | 100 | 25.78 | 30.00 |
| BPS HTTP | 500 | 152.73 | 129.30 |
| BPS WS | 40 | 27.00 | 27.66 |
| BPS WS | 100 | 69.45 | 76.32 |
| BPS WS | 500 | 747.45 | 746.11 |

500 并发 HTTP 的总内存分配均约 117 MiB。BPS 关闭路径微基准为 15.49/16.56 ns，强制 WS 开关缓存读取为 10.08/10.52 ns，两版均为每次 0 字节、0 次堆分配。

首次新版 HTTP 批次曾明显偏慢，编译结束后反向复跑未持续出现。上述结果受本机负载影响，仅能验证当前模拟路径的正确性与粗略性能，不能换算成真实 OpenAI 延迟或正式环境并发容量。
