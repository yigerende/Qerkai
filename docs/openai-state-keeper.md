# 上游状态管理

管理员菜单位于“公告”上方，路径 `/admin/openai-state-keeper`。代理添加、账号添加/导入、采集配置、账号状态、最近 200 条采集记录都在此页。默认关闭，采集和请求注入分别控制。

## 使用

1. 添加专用 HTTP/HTTPS/SOCKS5 采集代理，选择 OpenAI OAuth 账号及实际使用的模型。
2. 保存配置，执行“立即采集”。自动刷新开启时也会排队采集。
3. 检查原始 HTTP 返回码与采集结果，再决定是否启用请求注入及适用分组。

后台允许不同账号并发采集，最多同时 50 个，超出部分排队；同一账号在排队、采集及取消退出期间均不会重复启动。每次最多 45 秒。关闭、修改采集配置或服务退出时取消所有旧任务；旧任务不能把结果写回新配置。

勾选“自动采集与刷新”后显示一个秒数输入框，保存后生效。`auto_collect_interval_seconds` 为 1–86400 时，每个账号在上次采集结束后等待该秒数再采集，成功和失败使用相同间隔，不再被到期刷新或失败退避提前触发。设为 0（旧配置默认值）时沿用原有自动续期：默认缓存一小时、提前五分钟刷新，连续失败指数退避至最多 30 分钟。首次启用且没有采集结果的账号立即排队；关闭自动采集后仍可手动采集。

## 实际协议与实验边界

采集在进程内调用 Qerkai 的 `/v1/chat/completions` 兼容处理逻辑，输入消息体为：

```json
{"model":"gpt-6-astra","messages":[{"role":"user","content":"hi"}]}
```

模型取自页面配置，复用正常 Chat Completions 的模型映射、Responses 转换和 OAuth 请求构造。最终发送到 `POST https://chatgpt.com/backend-api/codex/responses`，使用选定账号的 OAuth 凭据及采集代理。页面分别展示本地入口与实际上游地址。

内部直接指定账号，不经公开 API 的账号调度与用户计费，不需要保存一把额外的 Qerkai API Key。仅在本次采集使用账号副本覆盖代理，不修改账号管理中的业务出口。采集固定走 HTTP，以便读取原始状态码和响应头；在 Chat Completions 响应转换及错误处理之前提取结果，不受业务强制 WS 配置影响。采集保留 45 秒超时与取消，不切换账号、不回退直连。

普通用户的 `/v1/chat/completions` 调用不带内部采集参数，继续执行原有的 WS 路由、响应转换、重试和错误处理。没有新增公开请求头或参数来绕过账号调度。

文章仅给出相对路径及本地 gpt-load 地址，未提供其真实上游地址及完整认证方式。这里采用本项目已经支持的 OAuth 兼容请求路径，不宣称已经验证文章的全部机制。

只有实际返回 **HTTP 292** 且 `current_turn_state` **响应头**非空并符合字符限制，才写入该账号的 State 文件并标记为已采集。响应正文中的同名字段、HTTP 200、只有 292 没有状态、普通 `x-codex-turn-state`、上游失败均不会成为可注入状态。

此前直接向 `api.openai.com/v1/chat/completions` 使用 OAuth 凭据实测，返回 HTTP 429 `billing_not_active`；现在已替换为上述本地兼容路径。HTTP 200 或普通 Codex 回合状态不代表文章机制已验证，必须实际观察到 292 与指定响应头。

2026-09-18 更新重启后，通过管理页为两个 OAuth 账号各采集一次，确认进程连接到当前所选采集代理。两次原始上游响应均为 HTTP 200，仅观察到普通 `x-codex-turn-state`，没有 `292 + current_turn_state`，因此没有保存或注入状态。

实验注入字段采用文章所述的 `current_turn_state`：HTTP 使用同名请求头，HTTP 入站转强制 WS 时写入本次 `response.create.client_metadata`。后者是实验映射，尚无真实上游接受及改善效果的证据；页面的“已采集”仅表示观察到了指定返回码和字段，不代表“已验证改善”。不会把它自动改名为官方同回合专用的 `x-codex-turn-state`。

注入只适用于所选账号、分组和完全相同的上游模型的 `/responses` 请求；不改变模型、提示词、工具内容、CPA 通知或 502/503 重试预算。WS 注入发生在本次业务消息写出前，不修改池内握手头或连接选择，避免关闭后池内连接遗留本功能添加的头。

缓存一小时、提前五分钟刷新是可配置的本地实验参数，不代表上游状态的真实有效期。状态缺失、过期、账号认证变化或关闭注入时直接走现有路径；业务请求不查询采集服务、不访问数据库、不等待采集。

## 保存与观察

配置保存在 settings 表。每个账号独立保存一个 State 文件：`$DATA_DIR/openai-state-keeper/account-<ID>.state`；未设置 `DATA_DIR` 时为工作目录下的 `data/openai-state-keeper/`。文件使用从服务端 JWT 密钥派生的独立 AES-GCM 密钥加密，临时文件写完后原子替换；保存失败时不启用新状态，仍有效的旧状态可继续使用。

重启时后台读取文件，校验账号、认证指纹、模型、采集代理、接口及有效期，符合当前配置才恢复。关闭功能时不恢复或注入；过期或不匹配时重新采集。业务请求只读内存，不逐请求读取文件。最近记录和计数从头开始，页面只显示状态摘要标识，不显示状态原文、访问令牌、代理密码或上游响应正文。采集使用管理员选择的账号额度，不生成用户调用的计费记录。

配置每 30 秒在实例间同步；本实例保存立即生效。每个实例维护自己的采集队列、文件和内存状态，当前版本建议先在一个实例、一个测试分组和两个账号验证。不支持依靠共享文件实现多实例协调或全局单次采集。

管理 API：`GET/PUT /api/v1/admin/openai-state-keeper`，`POST /api/v1/admin/openai-state-keeper/collect`。均使用现有管理员认证及审计。
