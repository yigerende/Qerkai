# 上游状态管理

管理员菜单位于“公告”上方，路径 `/admin/openai-state-keeper`。代理添加、账号添加/导入、采集配置、账号状态、最近 200 条采集记录和原有注入配置都在此页。采集和请求注入分别控制，默认关闭；先验证采集不需要删除或强制关闭原有注入功能。

## 使用

1. 添加专用 HTTP/HTTPS/SOCKS5 采集代理，选择 OpenAI OAuth 账号，模型每行一个，最多 20 个。新配置默认 `gpt-5.5`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-6-astra`；已有单模型配置继续有效。
2. 保存配置，执行“立即采集”。自动采集开启并填写大于 0 的间隔时也会定时采集。
3. 在“账号状态”或“采集记录”查看 HTTP 返回码、响应头值长度及采集结果。
4. 在“允许保存的响应头长度”填写逗号分隔的长度，例如 `292,332`，只有匹配的有效头值才能写入 State 文件。空项和重复项自动忽略，`292,,332` 等同于 `292,332`；留空表示不限制长度。
5. 在“账号状态”点击“详情”，查看该账号最近一次取得的有效 `x-codex-turn-state` 响应头全文、长度、采集时间、是否符合规则及是否已写文件，可复制完整响应头。被长度规则过滤的头值也可查看。
6. 账号状态默认每个账号收起为一行，汇总已保存、待人工和采集中模型数；点击账号展开各模型的状态、返回长度、最近采集时间和计数，自动刷新保留展开状态。“状态值”显示已保存 State 的首尾摘要及 SHA-256 指纹；点击摘要或“查看”读取该账号、该模型文件解密后的完整 JSON。未写入文件时按钮禁用。完整响应头与文件内容均不打码，仅在管理员点击详情时读取。
7. “一键重试待人工项”仅为当前采集范围内已暂停且未排队、未采集的账号模型重新排队，继续使用当前代理优先级、并发及重试配置。后端按最新状态筛选，重复点击不重复排队；已成功的其他模型不受影响。
8. 采集账号支持“全选”和取消全选；输入搜索条件后仅选择或取消当前搜索结果，保留其他已选账号。选择随配置保存，不自动发起采集。
9. “采集分组”支持多选，持久保存分组 ID，动态纳入其中全部 OpenAI OAuth 账号，包括以后新建、导入或移入的账号。实际采集范围为“手动账号 + 所选分组成员”的去重合集；分组成员标记为“分组”，不会被全选操作固化成手动账号。账号移出全部所选分组后退出范围，仍被手动选中的账号保留。采集分组与注入范围的分组分别设置。

分组范围在保存、打开或刷新页面、手动采集前同步，后台每 30 秒同步一次，不依赖页面保持打开。空分组可以保存并保持启用，之后加入账号即可自动纳入；按原来的定时采集、降智扫描和响应触发开关决定何时实际采集，不新增强制采集入口。分组成员没有前端 500 条加载限制。账号状态自动显示新增账号，失效账号保留浅红状态并跳过采集。成员变化保留其他账号的 State、WS 版本和采集任务；离开范围的账号停止后续采集，再次加入仍恢复原有 State、自动恢复计划和需要人工处理的暂停记录。

“采集总并发数”支持 1–500，默认 50，限制所有账号和模型正在执行的采集请求总数。“单账号采集并发数”支持 1–100，默认 1，限制同一账号全部模型合计的在途请求。同账号同模型只执行一个采集任务，不同模型分别管理。“每轮请求上限（全部代理合计）”支持 1–100，默认 3；所有已预留的并发请求均占用次数。每次请求最多 45 秒。

“失败后重试轮数”支持 0–100，默认 0；“重试间隔（s）”默认 5，开启重试时须为 1–86400。一轮没有成功保存 State 时，等待间隔及随机抖动后再执行下一轮。每个连续采集周期的请求总上限为 `(1 + 重试轮数) × 每轮请求上限`，包含所有代理、所有已预留的并发请求，不再乘以代理数。成功立即停止；普通失败耗尽后进入自动冷却，不要求人工重新点击。关闭采集会取消当前请求及等待，并停止自动恢复。

采集代理支持多选，最多 20 个，按列表从上到下的优先级执行。“切换代理失败次数”默认 2：每个代理最多执行这一小批请求，均未成功就换下一个，不等待当前代理用完全部轮数。连接错误、代理故障、403 和 5xx 可以提前切换。批次结束后才使用下一代理，当前并发结果不会串入下一批。冷却后从上次尚未尝试的下一代理继续；取得 State 后，下次新的采集周期重新优先第一个代理。

采集专用 HTTP 连接禁用复用，每次请求使用新的代理连接；按连接分配出口的动态代理可以重新选 IP，固定或粘性出口仍由代理商决定，不保证每次换到不同 IP。业务 HTTP、强制 WS、WS 优化调度的连接池不受影响。

“距上次成功”显示距离成功保存 State 的分钟数，采集失败不会重置。账号汇总行取各模型中距上次成功时间最长的值，展开后各模型独立显示；超过 40 分钟浅蓝、达到 50 分钟浅黄、超过 60 分钟浅红，无成功记录不着色。

“一键重试冷却中”只对采集范围内空闲、未暂停且账号可用的冷却项重新排队。此管理员操作主动解除目标账号的本地 429 冷却，并在已达到小时上限时重置该账号的本地采集窗口；同账号全部模型共享该窗口，已保存 State 不变。请求间隔、并发限制及近期 429 后的单并发试探仍保留，再遇到 429 会重新冷却。排队中、执行中、失效账号和待人工项跳过；重复点击不重复排队，采集关闭时不可执行。

### 自动恢复与限速

- 每账号每 5 分钟、每 10 分钟采集上限支持 0–10000，默认 0（不限），不改变旧配置的采集节奏。与小时额度一样，使用从首次采集开始的固定时间窗口，所有模型和代理共享；三个窗口及 429 等待同时生效，达到任一上限后等全部限制解除再继续。发送前原子预留并持久化，换代理、改模型、重启不会清零。“一键重试冷却中”会同时重置已耗尽的短周期窗口。
- 账号状态展开后的“采集 / 成功 / 注入”列同时显示账号 5 分钟、10 分钟和本小时已用次数与上限。各模型展示同一账号共享用量，短周期上限为 0 时显示“不限”。
- 代理优先级显示每个代理的累计成功次数，仅取得合格 State 且成功保存时加 1，失败、长度不符和被取消的并发结果不计入。统计按代理 ID 单独保存在数据目录 `openai-state-keeper/proxy-successes.json`，删除账号、删减模型、重排或取消勾选代理、重启不会清零；删除后重新创建的代理是新 ID。计数从此功能上线开始累计，旧记录无法准确追溯全部历史成功次数。统计文件异常会显示提示并自动重试，不清空历史计数。

- 单账号请求间隔默认 1 秒，支持 0–300 秒，叠加最多 20% 的正向随机抖动；同一账号的所有模型共用启动节奏和并发上限。0 可关闭启动间隔，但仍受并发、冷却和小时预算限制。
- 普通失败在连续周期结束后冷却，默认从 30 秒指数增加，最大 900 秒，含随机抖动。冷却释放工作位置，到期后台自动继续，不依赖普通定时采集开关。没有取得合格长度不会删除旧 State。
- 429 立即阻止该账号全部模型继续启动请求，优先遵守 `Retry-After` 秒数或 HTTP 日期；上游给出的等待长于本地上限时仍遵守上游要求。并发返回的一批 429 只增加一次退避等级。冷却后以单并发试探，取得合格 State 后恢复所设并发。冷却期间换代理、重复触发或普通手动采集均不能绕过等待；管理员专用“一键重试冷却中”可主动解除本地等待。
- 每账号每小时采集上限默认 120 次，全部模型合计，支持 1–10000。使用从该账号首个请求开始的一小时窗口；请求发送前保存预算，达到上限后等窗口结束自动恢复。进程异常退出可能把已预留但未发出的请求计入预算，避免少算后重复打满。预算和 429 冷却独立于模型列表持久化，改配置、增删模型或重启不能清零。
- 401、明确的账号失效、模型不可用或无权限、计费未启用或明确额度不足、文件写入失败等需要人工处理。普通网络故障、无响应头、长度不符、常规 429、502/503 不进入人工暂停。
- 例如允许保存 332、采集持续返回 356 时，轮数耗尽后仍会按配置自动继续，直到取得允许保存的长度；重启后也恢复这项计划，无须点击“待人工”按钮。429 冷却和账号小时上限仍生效，等待到期后自动恢复，不把 356 当作账号失效。
- 账号状态显示自动冷却、下次重试时间、原因、账号小时用量和当前并发上限。请求注入与响应触发均保持各自开关；关闭请求注入也会停止继续执行由业务返回信号发起的恢复计划，手动及两个定时入口不依赖注入开关。

已有配置缺少的新参数按上述默认值加载。旧版因普通失败耗尽或进程中断而暂停的任务升级后转为自动冷却；凭据、文件故障等人工暂停保留。已保存的并发、轮次数、代理顺序不被自动改写。

State 文件记录实际成功采集的代理。调整优先级或增加备用代理不会清除已有 State；从选择范围移除其来源代理时，按原有代理范围校验使该 State 失效。旧 `proxy_id` 配置按单代理兼容读取，新配置以有序 `proxy_ids` 为准。

打开或刷新状态管理页面时会同步清理已删除账号、代理的配置引用；后台每 30 秒也会同步。删除账号同步从账号状态及待人工重试数量中移除；保留其余账号和代理的优先级。账号或代理全部删除后自动关闭采集，代理全部删除时也清空旧 `proxy_id`，需要重新选择后启用。禁用、过期或查询失败不视为删除。清理保留其他采集配置和注入复选框设置；被移除代理产生的 State 仍按上述来源范围校验失效。

三个自动触发入口互相独立，使用相同的采集配置：

1. **请求返回信号**：同时开启“请求注入”和“请求响应触发采集”后，检查选中账号、模型和分组的业务响应。新返回的 `x-codex-turn-state` 长度命中“降智响应头长度”就异步排队采集，不等待、不重新发送当次业务请求。新开关默认关闭，旧配置升级后也关闭；关闭时保留正常 State 注入和注入次数记录，不检查返回长度、不触发响应采集。这个入口不要求打开两个定时开关。
2. **定时自动采集**：仅按账号状态列表的“最近采集时间 + 自动采集间隔（s）”判断是否到期，不要求综合结论为降智。手动、返回信号、普通定时、降智扫描完成采集后都会更新同一个最近采集时间，并顺延下一次普通定时采集；从未采集的账号直接排队。0 表示不定时采集，已暂停账号仍须人工恢复。
3. **定时降智扫描**：按独立的“降智扫描间隔（s）”读取最新综合检测结论，只为判定降智的所选账号排队采集。它读取已有检测结果，不代替“降智检测设置”中的答题与模型检测任务。

两个定时功能都不依赖“请求注入”开关；关闭“请求注入”则业务侧不再注入、不观察返回长度、不触发响应采集。手动“立即采集”始终按管理员选定账号执行。

重复保存相同配置不会取消正在执行的采集、清空队列或重置定时。修改并发、代理等其他配置时，降智扫描保留原来的下次执行时间；修改降智扫描间隔则按上次扫描时间加新间隔计算。普通定时仍按最近采集时间计算，已到期、刚启用的自动任务或新增且从未采集的账号仍按对应开关正常调度；保存按钮本身不作为额外采集入口。

采集账号可按分组筛选后全选，保留其他分组已选账号，不改变注入分组范围。账号异常、禁用或过期时保留配置和 State，账号状态行显示浅红色，手动、定时、返回信号等采集入口均跳过。采集收到 401 或明确的账号失效错误会停止该账号所有模型的重试和排队采集，停止标记跨配置保存和重启保留。外部接口或账号管理写入新的非空访问令牌，或已观察到的异常状态恢复启用后，账号再次符合采集条件时，后台同步自动解除账号失效导致的暂停并继续未完成采集，无须人工点击；后台每 30 秒同步，打开页面或手动操作也会同步。旧版本已清除认证标记但仍保留账号失效暂停的记录同样自动恢复。429 冷却、小时预算、其他文件或模型权限故障暂停保留；关闭采集时不发请求，关闭请求注入或响应触发后不恢复原来由响应触发的续采。普通 429、502/503 不视为账号失效。

降智检测的答题请求沿用原单账号测试路径和账号代理；开启请求注入且账号、实际上游模型、账号所属分组匹配时，携带同账号同模型已保存的 `x-codex-turn-state`。开启“请求响应触发采集”时，其返回长度同样可异步触发采集，注入来源显示“降智检测”；关闭注入后保持原检测请求。

一轮内首个符合规则且成功保存的 State 生效，然后取消其余并发请求并等待它们退出，迟到结果不得覆盖。普通失败耗尽后保留旧 State 并自动冷却；自动计划按账号和模型合并，重复信号不会重置等待或叠加新任务。人工暂停、自动恢复进度和预算均持久化；中断任务重启后冷却再继续。普通手动重新采集可以提前开始普通失败的下一周期，但不能绕过账号的 429 冷却或小时预算；主动解除限速仅由“一键重试冷却中”执行。

## 实际协议与实验边界

采集在进程内调用 Qerkai 的 `/v1/chat/completions` 兼容处理逻辑，输入消息体为：

```json
{"model":"gpt-6-astra","messages":[{"role":"user","content":"hi"}]}
```

模型取自页面配置，复用正常 Chat Completions 的模型映射、Responses 转换和 OAuth 请求构造。最终发送到 `POST https://chatgpt.com/backend-api/codex/responses`，使用选定账号的 OAuth 凭据及采集代理。页面分别展示本地入口与实际上游地址。

内部直接指定账号，不经公开 API 的账号调度与用户计费，不需要保存一把额外的 Qerkai API Key。仅在本次采集使用账号副本覆盖代理，不修改账号管理中的业务出口。采集固定走 HTTP，以便读取原始状态码和响应头；在 Chat Completions 响应转换及错误处理之前提取结果，不受业务强制 WS 配置影响。采集保留 45 秒超时与取消，不切换账号、不回退直连。

普通用户的 `/v1/chat/completions` 调用不带内部采集参数，继续执行原有的 WS 路由、响应转换、重试和错误处理。没有新增公开请求头或参数来绕过账号调度。

文章仅给出相对路径及本地 gpt-load 地址，未提供其真实上游地址及完整认证方式。这里采用本项目已经支持的 OAuth 兼容请求路径，不宣称已经验证文章的全部机制。

采集条件为 **HTTP 200** 且原始 HTTP 响应头 **`x-codex-turn-state`** 非空、满足 1–16384 字节的可见 ASCII 字符限制。取得有效头值后立即完成采集，不等待模型输出；“已采集”不表示已检查响应正文或验证模型效果。响应正文或 SSE 元数据中的同名字段不能代替 HTTP 响应头；非 200、缺少响应头或格式无效时不保存新状态。

**292、312、332、356 等数字表示响应头值的长度，不是 HTTP 状态码。** 保存规则由管理员按实际账号情况设置，不把某个长度内置为质量好坏的判断标准。`allowed_state_lengths` 为空时允许全部有效长度，否则只允许指定长度；最多 100 个不重复的 1–16384 整数。手动与自动采集共用后端筛选，长度不符时仍记录 HTTP 状态、长度和详情，但不更新可用缓存或写入文件，也不覆盖先前符合规则的账号文件。修改规则后，不符合新规则的旧缓存会失效，重启时也不会恢复不匹配的文件。此前把 292 解释为 HTTP 状态码、读取 `current_turn_state` 的实现有误，现已纠正。

2026-09-18 通过配置的住宅代理对同一个随机账号连续实测 10 次，请求模型 `gpt-6-astra`，均返回 HTTP 200 与长度为 356 的 `x-codex-turn-state`，头值每次不同；响应正文的模型字段均为 `gpt-5.6-luna`。这些是该轮实测结果，不能据此把某个头值长度解释为模型质量保证。

开启请求注入后，采集范围内、模型及分组匹配、凭据未变化且有有效 State 的 OpenAI OAuth 账号即可注入，不要求先判定降智，也不依赖降智检测总开关或两个定时开关。综合降智结论只用于“定时降智扫描”是否触发采集。HTTP 在实际发往上游的请求头设置 `x-codex-turn-state`；WS 在握手头设置同名字段，不写入业务 JSON 的 `client_metadata`。支持 Responses 和 Chat Completions 的兼容请求路径。开启“请求响应触发采集”时，没有可注入 State 的范围内请求仍可观察返回长度并触发采集。采集请求本身不注入，也不触发业务响应采集。

WS 连接按 State 版本隔离，原有主连接、备用、预热与新建的调度顺序在兼容连接内继续使用。State 更新后，后续请求不能复用旧 State 握手；正在执行的请求不中断。关闭注入后的请求也不能复用携带采集 State 的握手连接，因此首次切换可能正常新建连接。旧版本的预热结果不进入新版本库存。新握手头每条物理连接只观察一次；新收到的 `codex.response.metadata.headers` 可以提供当前请求的新信号，不把复用连接的旧握手头当作每轮响应。旧版本请求返回的信号不能触发新 State 重采。

CPA 通知、502/503 重试、下游响应转换与计费规则不变。关闭注入时，HTTP 不改请求头或正文，WS 使用原来的握手构造与调度参数，不进行响应长度采集触发。已有正在执行的请求按启动时配置完成。

“降智检测设置”增加答题异常、模型不一致两个可选条件以及“任一满足 / 全部满足”。沿用各条件的连续异常、连续正常次数，检测失败、没有样本和旧配置结果为待检测。账号管理“智商情况”第三行展示综合“降智 / 待检测 / 无降智”及原因。采集成功不会直接判定恢复正常，恢复由后续检测复核。

请求注入启用且账号位于注入范围内时，同账号、同检测模型保存新 State 后，模型一致性显示“新 State 待验证”，清除该模型旧的连续计数和当前异常标记，答题结果与历史记录保留。新 State 不直接算恢复：只用新 State 保存后开始的用户请求样本，按连续异常、连续正常阈值重新确认。日志开始时间由完成时间减请求耗时推算；缺少耗时的样本不用于新 State 验证。模型样本为空时保持待验证，不会额外请求 OpenAI；后台同步持久化该状态，重启不重复重置同一个 State。其他模型采集、过滤掉的长度和保存失败不触发重置。

State 不设固定过期时间，不根据本地经过时长淘汰文件、阻止注入或触发重采。配置中取消缓存时长、提前刷新和失败重试起始间隔；列表和详情不显示缓存截止时间。仍会校验账号归属、凭据、模型、代理及管理员设置的允许长度。业务请求不等待采集或访问采集文件。

## 保存与观察

### 综合降智暂停调度

“降智检测设置”的综合判断下新增 `pause_on_degradation`，默认关闭。开启后，综合结论确认降智会直接关闭账号原有的 `schedulable` 调度开关，账号管理按钮显示关闭。HTTP、WS、会话和 response-id 粘性调度沿用原来的关闭账号处理，不增加另一套调度过滤；正在执行的请求继续完成。账号状态、401/限流冷却不变。

暂停期间通过后台直接访问该账号复检，使用账号原来的业务代理；请求注入开启、有匹配 State 时照常携带。复检执行勾选的判断条件，同模型答题与模型检查共用一次请求，不同模型分别请求。模型从上游原始事件读取，不依赖用户使用日志，也不生成用户扣费记录。采集本身仍使用专用采集代理。

新 State 成功保存后唤醒复检队列，无需等待下一次用户调用。按照“异常 / 失败复测间隔”继续复检，综合结论连续正常达到“连续正常恢复次数”才解除降智暂停；采集成功本身不立即恢复调度。State、凭据或检测配置更新后重新累计恢复次数，旧请求结果不能确认新 State 恢复。没有模型名、检测失败、账号不可用都不会放行。最多按设置的并发数执行后台恢复检测，多实例由数据库锁避免重复执行。

暂停与恢复计数保存在数据库，调度变化写入现有调度事件表并刷新账号缓存。复检恢复或关闭该措施、降智检测时，仅重新开启由本功能关闭且账号仍可用的调度开关；此前已手动关闭的账号保持关闭。单独或批量手动关闭会取消自动开启资格。已到期、401、禁用账号不会被自动打开，其他冷却仍照常生效。内部 `quality_schedulable_restore` 仅记录是否允许自动恢复，不参与请求调度判断；旧版独立暂停标记会自动迁移并清除。账号管理的智商情况中可查看降智暂停、连续正常次数、下次复检时间及失败原因。普通未暂停账号的模型一致性仍使用原来的日志判断。

配置保存在 settings 表。每个账号、模型独立保存 State 文件：`$DATA_DIR/openai-state-keeper/account-<ID>-<模型SHA256>.state`；未设置 `DATA_DIR` 时为工作目录下的 `data/openai-state-keeper/`。使用模型摘要作文件名，模型名不能改变文件路径。文件使用从服务端 JWT 密钥派生的独立 AES-GCM 密钥加密，记录 `header_name=x-codex-turn-state` 与完整 `turn_state`，临时文件写完后原子替换；保存失败时保留旧文件。兼容旧的 `account-<ID>.state`，仅恢复给文件内记录的同一个模型。注入严格匹配账号与请求模型，不跨模型借用 State；HTTP 请求头与 WS 握手头均发送解密后的原始字符串。

重启时后台读取文件，校验账号、认证指纹、模型、采集代理、接口、响应头名称和长度规则，符合当前配置才恢复 HTTP 200、头值长度和已采集状态。旧文件中的 `ttl_seconds`、`expires_at` 不再参与判断，新的文件不再写入这两个字段。旧版 `current_turn_state` 文件不会当作本版本采集结果恢复，需重新采集。关闭功能时不恢复；不匹配时等待手动或明确配置的定时采集。

API 字段 `turn_state_length` 表示最近一次采集响应的 HTTP 头值长度，未取得响应头时为 0；失败刷新保留旧缓存。每账号模型另存 `account-<ID>-<模型SHA256>.runtime.json`，保存轮次、暂停、自动恢复时间、下个代理、累计次数和最近各 10 条采集、注入记录；账号共享预算另存 `account-<ID>.collection.json`，均不含 State 原文。业务记录经有界队列处理、后台批量落盘；队列满时普通观测记录可能丢弃，降智触发信号另按账号合并等待后台处理。异常退出可能丢失末尾尚未落盘的模型计数和观测记录，但账号请求预算已经在发送前保存。

账号管理新增“最近采集 / 注入”列，两行色条，悬停查看时间、来源、返回长度、尝试次数和结果，点击查看详情。注入成功只代表已携带 State 发送，不能等同于恢复满血。列表最多每批读取 100 个账号，不为每行发单独请求；隐藏列时不查询。采集使用管理员选择的账号额度，不生成用户调用的计费记录。

完整头值只在管理员点击“详情”时通过独立接口读取，响应设置 `Cache-Control: no-store`。详情的 HTTP 200、长度和采集时间对应最近一次取得有效响应头的采集，不混用后续错误响应的信息；被过滤的头值仅用于内存详情，不进入 State 文件。详情单独显示当前规则是否允许以及当次是否已写文件；从未取得有效头值时禁用详情按钮。State 文件查看接口只在列表标记为已写入时读取，并再次校验加密文件的账号、模型、代理、响应头名称、格式和当前长度规则；文件不存在或校验失败返回 404。关闭详情会清除前端原文，迟到的接口响应不会重新打开详情或覆盖另一个账号。详情不包含访问令牌、代理密码或上游响应正文；文件详情返回解密后的完整当前格式记录，旧固定到期字段不再展示。

配置每 30 秒在实例间同步；本实例保存立即生效。每个实例维护自己的采集队列、文件和内存状态。不支持依靠共享文件实现多实例协调或全局单次采集。

管理 API：`GET/PUT /api/v1/admin/openai-state-keeper`，`POST /api/v1/admin/openai-state-keeper/collect`，`GET /api/v1/admin/openai-state-keeper/accounts/:id/state`，`GET /api/v1/admin/openai-state-keeper/accounts/:id/file`。均位于现有管理员认证及审计中间件之后；两个详情接口均设置 `Cache-Control: no-store`。

账号列表批量接口：`POST /api/v1/admin/openai-state-keeper/recent`，参数 `account_ids`，一次 1–100 个不重复正整数。新增配置字段：`account_concurrency`、`max_attempts`、`degraded_state_lengths`、`response_refresh_enabled`（默认 `false`）、`degradation_scan_enabled`、`degradation_scan_interval_seconds`。允许保存与降智长度不能重叠；允许列表为空时也不保存配置的降智长度。
