# 降智检测

## 部署与迁移

1. 先升级 Qerkai，启动时自动执行 `236_account_quality_detection.sql`。
2. 在“公告”上方的“降智检测设置”配置并开启检测。默认关闭，避免升级后自动消耗额度。
3. 两个 space 的原题库仍保存在原数据库，可“导出原检测配置”，在 Qerkai 的“检测配置”导入后保存。导入不会自动开启。
4. 再升级 space，设置查询间隔、结果有效期、条件组合及踢出/切组动作。space 不再发起答题或读取使用日志。

## 检测行为

- 检测仅针对未删除的 OpenAI 账号。Qerkai 复用现有单账号测试服务及该账号的网络配置；space 不传代理。
- “检测配置”可多选定时检测分组。默认 `all_groups=true`，保留所有 OpenAI 账号（含未分组账号）的原行为；关闭全部分组后使用 `group_ids` 的并集，至少选一组。一个账号命中多组只执行一次，已删除分组不纳入。答题和模型两种定时检测、设置页立即检测、顶部统计与定时待检测数均按保存的范围执行；账号换组后按最新关系筛选，并在真正探测前再次检查。
- 账号管理的手动选中检测不受定时分组限制，但范围外账号只执行本次手动任务，不因此加入后续定时复测。两个检测项的手动标记独立持久化并分别消费；配置版本变更使旧标记失效。迁移 `238_account_quality_group_scope.sql` 自动添加这些字段，不修改账号原分组或调度状态。
- 答题与模型一致性独立定时，各自使用配置的并发数（默认 4，任意正整数），实际并发不超过待检测账号数；每批取最多 `max(32, 并发数)` 个到期账号。恢复复检也使用该并发配置；同一类任务用 PostgreSQL 会话锁防多实例重入。
- 两种检测只更新自己的到期时间，首次未检测账号优先于复测。立即检测保留已到期账号的排队顺序；正在执行的请求继续执行，不重复启动。
- 设置页面每 3 秒读取轻量进度，显示当前配置覆盖数、未检测数、待调度数、本批完成/失败/跳过数、运行账号和耗时。进度持久化在两个批次记录中，多实例共享；页面隐藏时暂停轮询，请求未完成时不重叠轮询。耗时和倒计时以服务器时间为基准。
- 标准答案支持纯答案或唯一的 `FINAL_ANSWER=` 行。也支持关键词、正则；可只看内容、只看耗时、或同时判断。耗时必须小于阈值。
- 每次有效答题后换下一题。网络、401、429、空响应及不完整响应记为检测失败，不累计答错次数，不切换题目。
- 模型检查查询每账号最近最多 3 条匹配发送模型的日志。有当前配置及当前 State 可用的日志就按日志判断，只有 1 条或 2 条也直接使用，旧日志不会重复计数；没有有效日志时，本轮直接向该账号发送一条 `hi`，从完整上游响应读取实际模型名，按原连续异常/恢复阈值累计一次。请求使用模型一致性配置的模型、账号原业务代理，开启注入且存在匹配 State 时照常携带；检测请求不生成用户扣费日志。网络错误、401/429、缺少模型名或响应不完整记检测失败，按失败复测间隔重试。相同模型的日期/latest 版本后缀仍视为版本别名。
- 两项异常/恢复次数独立。配置未变时保存不改变版本和计数；配置改变才生成新版本，在途旧版本结果不对外生效。保存不会提前答题、模型检测或恢复复检的既定时间，也不会把旧 State 重新当成刚采集成功；立即检测仍可主动提前，新采集成功仍按原流程触发验证。
- 新 State 待验证期间，如果本轮没有新增可计数的有效日志（包括查到的日志已统计过，或早于已有检测证据），也会后台补发一条 `hi`。每轮最多一条，按模型检测间隔继续累计；探测失败按异常 / 失败复测间隔重试，达到配置的连续正常或异常次数后结束待验证。普通检测有有效日志时不因日志已统计过而额外探测，有效日志为 0 时仍发送一条 `hi`。
- 新 State 保存后，普通账号通过约每 5 秒一次的后台同步将模型检测设为到期，再由模型队列按配置并发执行；这不是每 5 秒都发探测请求，实际开始还受运行批次和队列影响。降智暂停账号则唤醒独立恢复队列，后续按异常 / 失败复测间隔执行。立即检测可提前下一轮检测，同一个 State 的反复同步不会重置计数或绕过间隔。
- 顶部“新 State 待验证”单独统计模型状态 `state_pending`；“模型无样本”只统计尚未取得模型状态或 `no_samples`，不再包含待验证账号。
- 结果与历史独立存表。仅开启自动暂停措施时控制账号原有调度按钮，不修改账号分组、状态。历史每账号有上限，默认 200。
- 新历史用 `detection_kind` 标记本次是答题还是模型检测，页面只显示本次检测的结果；旧记录标为状态快照。账号结果额外提供 `question_execution`/`model_execution`，表示排队中、检测中、等待下次或已关闭，不改变供 space 使用的检测结论。
- 账号管理支持选中后点击“降智检测”，确认后仅提前调度所选 OpenAI 账号，使用已保存并启用的检测配置，复用原工作队列和并发限制，不额外启动探测线程。未选中账号原有定时任务不变。
- 本次进度分别跟踪答题和模型的新 `checked_at`，不会把上次结果或另一项的完成算作本项完成。显示完成、异常、失败、跳过和中断；不支持的平台/已删除账号跳过，配置变更时中断旧批次的等待。
- 跨页选择超过 100 个时顺序分批提交，随后每 3 秒只分批查询尚未完成的选中账号。关闭进度弹窗后可在账号页重新查看；离开或刷新账号页停止本地进度跟踪，但后台排队任务继续，结果保存在智商情况列和历史中。提交响应丢失不自动重复提交。

## 指定模型 State 有效期与调度

“上游状态管理”新增“调度必须有有效 State”，默认关闭，仅适用于 OpenAI OAuth。默认要求 `gpt-6-astra` 的最近成功 State 在 55 分钟内；模型与时长可配置。开启须同时启用采集、请求注入、降智检测和模型一致性检测，定时检测范围须为全部分组，防止新增或未分组账号无法被检查。未加入采集或注入范围的账号无法满足有效条件。

- 新增账号（页面、导入和外部 API）入库时关闭原 `schedulable` 按钮；不等待首次定时检测。重授权按现有“新采集成功前停用旧 State”策略处理，默认关闭按钮并等待新 State；允许复用旧 State 时仍校验同账号身份及成功时间。
- 已有账号在原模型一致性定时任务、立即检测或后台复检执行到时检查。缺少指定模型 State、不符合注入条件或已过期则关闭按钮。到期本身不启动新定时器，不拦截正在进行的请求；例如有效期 55 分钟、模型检测间隔 120 秒，到期后等下一轮检测执行到该账号再暂停，繁忙批次仍可能排队。
- 采集成功唤醒现有后台验证；恢复必须同时满足配置的综合降智恢复规则、连续正常次数和当前指定模型 State 有效。只有 State、只有答题通过，或只有过去的用户日志均不能直接恢复。复检期间 State 过期、更新、凭据变化或配置变化时，旧结果不能开启按钮。
- 复检使用原异常 / 失败复测间隔、并发数和队列；采集及后台检测可直接检查已暂停账号。批次及调度选账号逻辑不变。
- 自动恢复只重新打开由该功能关闭且仍可用的账号；人工关闭、401、禁用和账号到期不会被自动开启。关闭新开关只解除它自己的暂停原因，其他降智暂停继续保留。
- 账号管理“最近采集 / 注入”第一行显示指定模型的有效情况和剩余分钟，随原列表刷新更新；不新增每行定时器。

这是后台控制调度按钮的有效期，**不是 State 文件的删除时间或请求注入的新 TTL**。HTTP、WS、强制 WS、连接池和 CPA 首帧的请求处理代码不变。

## 对外接口

均在现有 admin 鉴权下，使用已有管理员令牌/管理密钥，不开放匿名访问。

| 方法 | 路径 | 参数 |
| --- | --- | --- |
| GET | `/api/v1/admin/account-quality/capabilities` | 无 |
| GET | `/api/v1/admin/account-quality/accounts/:id` | 单账号 ID |
| POST | `/api/v1/admin/account-quality/results` | `{"account_ids":[1,2]}`，最多 100 个唯一正整数 |
| GET | `/api/v1/admin/account-quality/accounts/:id/history` | 历史上限按已保存配置 |
| GET/PUT | `/api/v1/admin/account-quality/settings` | 设置与统计/保存完整配置 |
| GET | `/api/v1/admin/account-quality/progress` | 两项检测统计与有界批次进度，不返回题库或使用日志 |
| POST | `/api/v1/admin/account-quality/run` | `{"account_ids":[]}` 按已保存分组范围立即调度；指定 1-100 个账号时等同手动选中检测 |
| POST | `/api/v1/admin/account-quality/run-selected` | `{"account_ids":[1,2],"revision":"可选配置版本"}`；严格要求 1-100 个唯一正整数，空列表不能执行全部。返回版本、启用检测项、账号名、两项基准检测时间和跳过原因 |

结果接口返回 `version:1`、`server_now`、精简策略 `settings` 和 `accounts`。每账号有 `revision`、`version`、`question`、`model`；两种结果分别带 `status`、`degraded`、`failures`、`successes`、`checked_at`、`evidence_at`、`streak_started_at`、`next_at`、`error`。无有效结果时 version 为空。

结果读取不产生探测任务。最多两个并发查询，每次 5 秒数据库超时；账号页面只按当前页分批查询，隐藏列后停止该列查询。

space 只在所选条件有当前轮转周期的新鲜、已确认结果时执行动作；未知、过期、错误及禁用检测不当作异常。正常恢复同样需要新鲜证据。重复读取不累加次数，已完成动作不重做，失败动作可重试。同母号的踢出仍走原串行及间隔控制。

## 验证范围

单元测试覆盖答案匹配、连续计数、换题、模型日志去重、只读批量查询、版本隔离、锁竞争、单账号测试复用、space 过期/旧周期/错误/重复结果、切组恢复与同母号串行。另用隔离 PostgreSQL 实测迁移重复执行、双实例抢锁、32 账号有界并发、两种结果同时保存、历史上限和新服务实例读取。页面使用隔离模拟 API 检查，不调用真实账号。

排队修复新增 62 账号的 PostgreSQL 回归测试，覆盖首次检测优先、模型保存不推迟答题、手动调度与结果保存交错、慢请求的进度、多实例互斥、取消与超时、配置版本变更和中断批次识别。新增迁移 `237_account_quality_progress.sql` 自动建表并修复旧账号首次检测的排队时间。
